## Что это

Веб-мессенджер для семьи/друзей: личные и групповые чаты, медиа, стикеры/GIF, опросы,
голосовые/видеозвонки (WebRTC), заметки чата, папки, PWA с push-уведомлениями.
Язык интерфейса — русский.

- **Backend:** Node.js + Express + Socket.io + better-sqlite3 (синхронный SQLite). Папка `backend/`.
- **Frontend:** React 19 + TypeScript + Vite + Zustand. Папка `web/`.
- **Деплой:** backend — Amvera (Docker, том `/data` для SQLite; `amvera.yaml`); frontend — Vercel (сборка из исходников, `web/vercel.json`). `DEPLOY.md` местами устарел (упоминает Railway).
- **Рабочая ветка:** `devDK`. Основная: `main`.

## Конвенции и грабли

- **Сообщения в БД зашифрованы** (AES-GCM): поля `ciphertext/iv/auth_tag`. **Открытого текста at-rest НЕТ** (миграция 010 удалила колонку `search_text` и FTS5 — они хранили cleartext). Поиск — через «слепой индекс» (blind index): `message_search_tokens` хранит необратимые keyed-HMAC отпечатки ПРЕФИКСОВ слов (ключ HKDF-производный от `MESSAGE_ENCRYPTION_KEY`, `utils/searchIndex.js`); `searchMessages` хеширует слова запроса → находит кандидатов по индексу → дешифрует ТОЛЬКО их и сверяет подстроку. Открытого текста при этом нет (только хеши). Поиск по началу слова (префиксу); подстрока в СЕРЕДИНЕ слова индексом не покрывается. Индексация — в `_insertMessage`/`editMessage`/`forwardMessages` (хелпер `indexMessageTokens`); бэкфилл существующих — миграция 016. Вкладка «ссылки» опирается на 1-битный флаг `messages.has_link` (есть ли URL), который проставляется при записи/редактировании из плейнтекста ДО шифрования (`textHasLink`). Меняя логику сообщений — НЕ хранить текст в открытом виде; обновлять `has_link`, а не несуществующий `search_text`.
- **Удаление аккаунта и таблицы, ссылающиеся на `users(id)`**: `PRAGMA foreign_keys=ON` включён ВСЕГДА (`config/database.js`) — новая колонка/таблица с `REFERENCES users(id)` БЕЗ `ON DELETE CASCADE`/`SET NULL` сломает `deleteAccount()` первым же живым пользователем, у которого появится такая строка (баг именно так и нашёлся 2026-07-03: `calls`/`chat_notes`/`messages.sender_id`). Правило: если новая сущность должна пережить удаление автора (сообщение, звонок, заметка — то, что видят ДРУГИЕ участники чата), ссылку при удалении аккаунта нужно переносить на постоянного пользователя-заглушку `userService.DELETED_ACCOUNT_USER_ID` («Удалённый аккаунт», `id='deleted-account'`, заведён миграцией `017_deleted_account_ghost.js`) в `services/chat/teardown.js::deleteAccount` — НЕ удалять и не занулять чужой контент. Если сущность приватная и её можно спокойно потерять (не видна другим) — подойдёт обычный `ON DELETE CASCADE`/`SET NULL` в схеме, как у `sessions`/`friends`/`sticker_packs.owner_id`. Контент, унаследованный заглушкой, стареет и чистится `workers/deletedAccountCleanup.js` (ретеншн `DELETED_ACCOUNT_RETENTION_DAYS`, по умолчанию 180 дней) — сам аккаунт удаляется сразу, копится только то, что на него переехало.
- **Дизайн «Аврора»**: фиолетовый акцент `--accent`, градиент `--grad-accent` для главных кнопок, свечение `--glow`. Старый синий `#2f81f7` не возвращать.
- **В проекте НЕТ клиентского роутера** (react-router и т.п.) — всё приложение рендерится из одного `App.tsx` по внутреннему state. Публичные статические страницы без авторизации (`/privacy`, `/terms`) сделаны иначе: `main.tsx` проверяет `window.location.pathname` ДО рендера `<App/>` и рендерит отдельный компонент вместо него (см. `components/legal/LegalPage.tsx`). `web/vercel.json` уже редиректит любой путь на `index.html`, так что новый статический путь ничего не требует менять в конфиге хостинга — только добавить ветку в `main.tsx`.
- **simplewebauthn v9** — API именно девятой версии (см. коммиты cbb10504 и ранее), не обновлять вслепую.
- `web/dist/` в git частично устарел и игнорируется — **не коммитить**, Vercel собирает сам.
- `backend/data/*.db*` — локальная БД, **никогда не коммитить**.
- Backend не стартует без `JWT_SECRET` и `MESSAGE_ENCRYPTION_KEY`.
- **Бэкапы БД зашифрованы на уровне приложения** (AES-256-GCM, `utils/backupCrypto.js`) ДО загрузки в S3 — ключи S3 не дают доступа к содержимому. Ключ: `DB_BACKUP_ENCRYPTION_KEY` (64 hex), иначе HKDF от `MESSAGE_ENCRYPTION_KEY` (всегда включено). Опц. изоляция: `DB_BACKUP_S3_BUCKET` + `DB_BACKUP_S3_ACCESS_KEY_ID`/`_SECRET_ACCESS_KEY` (отдельный бакет/ключи только-на-запись). Объекты — `*.db.enc`; восстановление: `npm run restore-backup -- <файл|--s3 ключ> [out.db]` (`--list` для списка).
- Проверка фронта: `cd web && npm run build` (tsc + vite) — обязательна перед пушем.
- Тесты бэкенда: `cd backend && npm test`.
- Тесты фронта: `cd web && npm test` (vitest + @testing-library/react, jsdom). Появились
  вместе с i18n (2026-07-08) — до этого фронт не имел тестов вообще. Конфиг — `test` в
  `vite.config.ts` (`/// <reference types="vitest/config" />` вверху файла), сетап
