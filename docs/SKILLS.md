# Скиллы агента в этом репозитории

> Что такое скилл: папка с файлом `SKILL.md` — YAML-шапка (`name`,
> `description`) плюс инструкции в markdown. Это не код и не плагин: агент
> постоянно держит в контексте только `name` + `description` каждого скилла, а
> полное тело подгружает **лишь когда описание совпало с задачей** (или когда
> скилл вызвали вручную через `/имя`). Отсюда смысл: объёмное знание, нужное
> редко, не занимает контекст в каждом сообщении, но всплывает ровно в нужный
> момент.

## Зачем они здесь

`CLAUDE.md` — карта проекта, она читается всегда и целиком. Держать в ней ещё и
подробные процедуры невыгодно вдвойне: они раздувают каждый запрос и при этом
теряются среди остального — правило, растворённое в сорока строках журнала,
легко не заметить именно тогда, когда оно нужно.

Скиллы решают вторую половину задачи: процедура лежит отдельно, стоит ноль,
пока не нужна, и приходит сама, когда формулировка задачи попадает в её
описание. Правило «CLAUDE.md против скилла» простое: **постоянный контекст и
навигация — в `CLAUDE.md`; повторяющаяся процедура с граблями — в скилл.**

## Свой скилл проекта

### `blizkie-migration` — изменение схемы БД

**Когда срабатывает.** Задача касается новой таблицы или колонки, внешнего ключа
на `users(id)`, смены `CHECK`/`DEFAULT`, бэкфилла существующих строк — либо
удаление аккаунта падает с ошибкой FOREIGN KEY. Вызвать вручную:
`/blizkie-migration`.

**Что даёт.** Контракт файла миграции и нумерацию; запрет на правку уже
применённой миграции (и как обходить его — на примере `accent_color`); приём
пересборки таблицы, без которого SQLite не меняет `CHECK`/`DEFAULT`; развилку
`ON DELETE` — переносить ли сущность на заглушку «Удалённый аккаунт» или
достаточно `CASCADE`; напоминание, что тестовая схема в `smoke.test.js`
собирается **вручную** и новую колонку нужно добавить и туда.

**Почему именно скилл.** Правила нужны раз в несколько недель, весят пару
страниц, а цена забывчивости — продовый инцидент, который не ловится тестами
(баг 2026-07-03: `deleteAccount()` падал у любого пользователя, кто хоть раз
звонил). Идеальное соотношение «редко нужно / дорого забыть».

**Держать в актуальном состоянии.** Устаревшая инструкция хуже отсутствующей,
потому что ей доверяют. Меняются правила работы со схемой — правится и скилл, в
том же коммите. Тот же принцип, что у базы знаний ассистента
`web/src/assistant/faq.ts`.

## Внешний набор: `emilkowalski/skills`

Установлен целиком (12 скиллов) — анимации, motion и design engineering от
автора Sonner и Vaul. Профильно совпадает с фронтендом проекта: дизайн-система
«Аврора» построена на микро-анимациях.

| Скилл | Когда полезен здесь |
|---|---|
| `animate` | построить анимацию с нуля — порядок решений, свойства, кривые, прерывание |
| `animate-expo` | то же для React Native/Expo — пригодится при нативной обёртке (§3 STORE_LAUNCH_TZ) |
| `animation-vocabulary` | назвать эффект точным термином, когда его можно только описать словами |
| `apple-design` | жесты, пружины, bottom-sheet'ы, translucent-материалы — мобильная оболочка |
| `ask-sonner` | если тосты/баннеры ошибок будут переводиться на Sonner |
| `emil-design-eng` | философия полировки UI и деталей компонентов |
| `find-animation-opportunities` | найти места без анимации, где она уместна (read-only) |
| `improve-animations` | аудит всего motion-кода с приоритизацией |
| `write-swift` | Swift — понадобится на iOS-ветке нативной обёртки |
| `pick-ui-library` | подбор библиотеки под задачу — **только вручную** |
| `prototype` | несколько вариантов UI за раз с визуальным переключателем — **только вручную** |
| `review-animations` | ревью анимаций по высокой планке качества — **только вручную** |

Последние три помечены `disable-model-invocation: true` — автор намеренно закрыл
их от автозапуска: это тяжёлые «сессионные» скиллы, которые не должны срабатывать
от случайной фразы. Вызываются исключительно слэш-командой.

## Как это хранится и как восстановить после клона

- `.agents/skills/` — **реальные файлы** внешнего набора. Каталог универсальный:
  тот же набор зарегистрирован и для Claude Code, и для GitHub Copilot.
- `.claude/skills/` — то, что читает Claude Code. Для внешнего набора там
  симлинки на `.agents/skills/`, созданные установщиком; собственный
  `blizkie-migration` лежит там же обычным файлом.
- `skills-lock.json` — источник и хеш каждого внешнего скилла.

**Симлинки в git не хранятся** (на Windows-машинах проекта `core.symlinks=false`,
git развернул бы их в дубли файлов) — `.gitignore` исключает содержимое
`.claude/skills/`, кроме собственного скилла проекта. Поэтому после свежего клона
внешний набор нужно восстановить одной командой:

```bash
npx skills@latest experimental_install
```

Она поднимает всё по `skills-lock.json`. Собственный `blizkie-migration` в этом
не нуждается — он лежит в репозитории как обычный файл.

## Управление

| Команда | Что делает |
|---|---|
| `npx skills list` | что стоит в проекте (`ls -g` — глобальные, `--json` — машинно) |
| `npx skills find <слово>` | поиск новых в каталоге [skills.sh](https://skills.sh/) |
| `npx skills add <owner>/<repo>` | установить (`-g` глобально, `--skill a b` выборочно) |
| `npx skills remove <имя>` | удалить (без имени — интерактивно) |
| `npx skills update` | обновить всё или один скилл по имени |
| `npx skills experimental_install` | восстановить по lock-файлу |
| `/имя-скилла` | вызвать вручную в диалоге |
| `/skill-creator` | создать свой скилл, прогнать evals на срабатывание описания |

Свежесозданный скилл обычно подхватывается сразу; если в списке его нет —
перезапустите сессию (внешний набор при установке потребовал именно этого).

## Гигиена

- Скилл исполняется с полными правами агента — это инструкции, которым он
  следует. Чужой набор перед первым использованием **прочитать**, как ревьюят
  зависимость, а не как документацию.
- `npx skills update` меняет инструкции — смотреть диффом, что именно пришло.
- `description` — это триггер, а не аннотация. Формула, которая работает:
  что делает → когда применять → по каким симптомам узнать. Плохое описание =
  скилл не сработает и будет мёртвым грузом.
