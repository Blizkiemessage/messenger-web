## 0. Общие принципы качества (соблюдать во всех фичах)

- **Дизайн «Аврора».** Не хардкодить цвета/отступы — только токены из
  `web/src/styles/01-tokens-auth-layout.css` (`--accent`, `--grad-accent`,
  `--glow`, `--panel`, `--border`, `--muted`, `--bg`, `--card`, `--danger`…).
  Точечные новые стили — в слой `18-aurora-overrides.css` (он ДОЛЖЕН оставаться
  последним @import в `app.css`). Старый синий `#2f81f7` не возвращать.
- **Качество визуала = на уровне уже сделанного** (см. хаб «Настройки чата»,
  «Вопрос дня»): стеклянные панели, градиентные акценты, микро-анимации,
  `prefers-reduced-motion`, адаптив под мобильный, аккуратные пустые состояния.
- **Переиспользование.** Модалки → `modalOverlay`/`modalCard` + lazy-import в
  `ChatArea`; переключатели → `ui/Toggle`; плееры/вложения → `chat/messageBubble/*`;
  ввод сообщений → `chat/Composer` (параметризуется колбэками). Не дублировать.
- **Состояние** — Zustand-сторы (`web/src/store/*`). Realtime — строго через цепочку
  `socketServer.js` → `socketClient.ts` (emit) → `hooks/useSocket.ts` (подписка).
- **Безопасность/приватность.** Текст сообщений шифруется at-rest (AES-GCM,
  `ciphertext/iv/auth_tag`) — НИКОГДА не хранить плейнтекст. **Репозиторий
  публичный**: секреты только в env (Amvera/Vercel), никогда в коде/`VITE_*`.
  Pre-commit хук в `.githooks/` это контролирует.
- **Схема БД** — новый файл-миграция в `backend/src/db/versions/NNN_*.js`
  (идемпотентно, применяется автоматически при старте).
- **Гейты перед пушем:** `cd web && npm run build` (strict tsc+vite) +
  `cd backend && npm test`. Интерфейс — на русском.

**Принцип реализации (поэтапно — можно БЕЗ ИИ на старте).**
- v1: **детерминированный FAQ** — реестр интентов (вопрос/ключевые слова →
  готовый ответ + набор deep-links). Никаких внешних вызовов, нулевая стоимость,
  предсказуемо. Контент — по реальным фичам проекта.
- v2 (опц.): подключить LLM для свободных формулировок поверх той же базы знаний

**Тонкости.** Контент-база знаний должна жить рядом с фичами и обновляться при их
изменении (иначе устареет). Ответы — только про приложение, без доступа к личным
данным (это Этап D). Deep-links обязаны быть валидными (реестр действий).

**Критерий готовности.** Топ-15 вопросов «как сделать X» отвечаются точно, с

## ЭТАП D. Ассистент по данным чатов («когда ДР у мамы?», «встреча с Антоном?»)

**Цель.** Приватный семейный «второй мозг»: ответы на вопросы по СВОИМ чатам и
профилям. Самая ценная, но и самая чувствительная/дорогая фича — делать последней.

**Поведение / UX.**
- Запрос в ассистенте → ответ + **обязательная ссылка на источник** (сообщение/
  профиль, откуда взят факт). Без пруфа «уверенных» ответов не давать.
- Полная настройка доступа (см. приватность).

**Принцип реализации.**
- **Структурные данные без LLM:** дни рождения — из `users.birth_date`;
  запланированные сообщения/встречи — из соответствующих полей. Это быстро, точно,
  дёшево — делать в первую очередь и для многих вопросов хватит.
- **Семантика через LLM:** «когда встреча с Антоном» → отобрать кандидатов
  (поиск/недавние сообщения нужного чата) → **дешифровать в памяти** → отдать
  модели на извлечение. Это ровно паттерн `aiSummaryService.collectMessages` —
  переиспользовать его, не изобретать заново. Кэш ответов (есть таблица
  `chat_summary_cache` — аналогично) + строгий rate-limit.

**Тонкости — ОБЯЗАТЕЛЬНО.**
- **Приватность (ключевое).** По умолчанию ВЫКЛ, строго **opt-in**. Настраиваемые
  области доступа: «только структурные данные (ДР/события)» vs «читать сообщения»;
  allowlist по чатам. Пользователь должен явно понимать и соглашаться.
- **Внешний LLM = данные покидают сервер.** Для «приватного» мессенджера это
  напряжение — проговаривать честно в UI согласия. Локальная модель приватнее, но
  дорого/сложно; при нулевом бюджете реалистичен внешний LLM + прозрачность.
- **Стоимость.** LLM платный → агрессивный кэш + лимиты; хороший кандидат в
  **платную фичу** (привязать к будущей монетизации).
- **Галлюцинации.** Всегда показывать источник; при неуверенности — честно «не
  нашёл», а не выдумка. Никогда не хранить расшифрованный текст/ответы в открытом
  виде дольше необходимого.

**Критерий готовности.** На вопросы по ДР/событиям отвечает точно и без LLM; на
семантические — с источником и opt-in; приватность настраивается; есть кэш/лимиты.

## Принцип позиционирования (не забывать при дизайне фич)
Blizkie — для **близкого круга / семьи**, НЕ «убийца Telegram». Выигрываем
глубиной, уютом, памятью и приватностью, а не паритетом фич. Каждая фича должна
усиливать привычку возвращаться и ценность для маленького доверенного круга.
